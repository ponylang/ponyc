## Fix use-after-free when an object is reached as both tag and val or iso

The garbage collector could free objects that an actor could still reach. This could happen when a message, or an actor's fields, held the same object both as a `tag` and as a `val` or `iso`, either directly or through other objects. For example, `be take(t: Foo tag, v: Foo val)` called as `take(foo, foo)` could trigger it, as could an actor with a `Foo tag` field and a `Foo val` field that hold the same object received from another actor. When it happened, the objects that the `val` or `iso` referred to could be freed while still in use, and the actor could then read freed memory. Whether it happened depended on the order in which the garbage collector reached the two references, and that order doesn't always follow the order in the source code. Those objects are no longer freed while still in use, whichever order the garbage collector reaches the references in.
