## Build ponyc with LTO when using a release preset

The `release`, `x86-64-release`, `armv8-release` and `armv8-a-release` CMake presets now set `PONY_USE_LTO`, which applies when you build ponyc with Clang. Building with GCC or MSVC skips LTO and says so at the configure step, because those toolchains need their own archiver and linker plugin before an LTO static library will link. The Windows presets don't set it at all. On a 64-core x86-64 Linux machine, compiling `packages/stdlib` with the resulting compiler drops from 201 to 186 seconds, and the front end through reachability analysis from 59 to 47 seconds. Configure with `-DPONY_USE_LTO=OFF` to build without it.

LTO reaches the `ponyc` binary and nothing that gets installed. `libponyrt.a`, `libponyrt-pic.a`, `libponyc.a` and `libponyc-standalone.a` all hold native objects whether or not it is set, so linking a Pony program and embedding the compiler as a library cost the same either way. libponyc's sources are compiled twice to keep it that way, which adds about a minute to a full build on a 64-core machine.
